# Asset Grid Cutter 开发计划

## 项目概述

Asset Grid Cutter 是一个本地素材表切割工具，用于把 AI 生成的网格素材大图拆成独立 PNG 资产，并提供本地网页 GUI、Tk GUI、CLI 和可复用 Codex skill。

当前重点目标：

- 让单张素材表可以更智能地识别网格并切割。
- 让切割结果适合后续高清放大流程。
- 让已有切图目录可以直接批量放大。
- 保持 Windows 本地使用流程尽量简单。

## 技术架构

- 核心处理：`asset_grid_cutter.py`
  - 网格检测、内容块检测、切图、裁边、透明背景、预览图、目录结构输出、CLI 放大。
- 网页 GUI：`asset_grid_cutter_web.py`
  - 基于 Python 标准库 `ThreadingHTTPServer` 提供本地网页。
  - 支持拖入单张图片自动分析切割。
  - 支持拖入已有切图目录或选择目录后直接放大。
- Tk GUI：`asset_grid_cutter_gui.py`
  - 作为兼容性备用图形界面。
- Codex skill：`skills/batch-image-upscale`
  - 用 Pillow `LANCZOS` 批量放大目录图片并保持目录结构。
- 依赖：
  - `Pillow`
  - `numpy`

## 模块划分

### 网格识别

- 灰色网格线检测：适合有浅灰分隔线的素材表。
- 内容块检测：适合无明显网格线、但素材排列规律的图片。
- 固定行列回退：用户手动指定 `rows x cols` 时可强制等分。

### 输出结构

默认输出结构：

```text
sheet_cut/
  01/01.png
  02/02.png
  preview.png
  manifest.json
```

原因：

- 每个资产独立文件夹，便于后续高清放大工具一图一目录处理。
- 文件名短，方便人工浏览和排序。
- 放大结果可以写入平行目录 `sheet_cut_upscaled`。

### 放大流程

当前有两种入口：

- 项目内网页和 CLI：`--upscale --scale 2`
- Codex skill：`batch-image-upscale`

当前后端：

- Pillow `LANCZOS` 快速放大。

后续可扩展后端：

- Real-ESRGAN
- ComfyUI
- OpenAI Images API 或其他图像 API

## 问题经验总结

### Python 3.14 移除 `cgi`

问题：

- 网页端启动时报错 `ModuleNotFoundError: No module named 'cgi'`。

原因：

- Python 3.14 已移除标准库 `cgi`。

处理：

- 改用 `email.parser.BytesParser` 解析 `multipart/form-data`。

经验：

- 本地工具应尽量避免依赖已废弃标准库。
- README 需要明确 Windows 使用 `python` 命令启动。

### 无网格线图片识别失败

问题：

- 某些 AI 素材表没有真实浅灰网格线，旧逻辑会退回默认 `6 x 12`，导致切错。

原因：

- 旧检测器只看跨整张图的浅灰分隔线。

处理：

- 新增内容块投影检测，根据背景差异和素材分布推断行列。

经验：

- 网格类素材至少需要三层识别策略：真实网格线、内容块分布、手动行列回退。

### 输出结构不适合后续放大

问题：

- 所有切片平铺在一个目录，不利于一图一目录的高清放大流程。
- 文件名过长，不利于人工检查。

处理：

- 默认改为 `sheet_cut/01/01.png`。
- 保留 `--flat-output` 和 `--long-names` 作为兼容选项。

经验：

- 素材处理链路应优先服务下一步工作流，而不是只完成当前切图动作。

### 浏览器无法直接读取本地目录路径

问题：

- 把已有切图目录拖进网页时，旧逻辑会当成图片文件处理，出现坏预览和 `Failed to fetch`。

原因：

- 浏览器安全模型不允许网页直接拿到本机绝对目录路径，只能拿到用户选择/拖入的文件内容和相对路径。

处理：

- 前端识别目录拖拽，上传目录文件及相对路径。
- 后端在 `web-work/uploads` 中重建临时目录，再输出到 `web-work/outputs/*_upscaled`。

经验：

- 网页端目录流程应设计成“上传目录内容”，不要依赖本地绝对路径。

### Codex skill 与项目 API 的边界

问题：

- 误以为 Codex 的 `imagegen` skill 可以直接作为网页项目的运行时 API。

结论：

- Codex skill 是 Codex 会话能力，不是 Python 网页服务可直接调用的运行时接口。
- 项目要一键 AI 放大，需要接入真实 API 或本地模型服务。

处理：

- 先实现独立 `batch-image-upscale` skill，使用 Pillow 快速放大。
- 后续若接 AI，需要明确后端：Real-ESRGAN、ComfyUI 或图像 API。
